# Voice masking release readiness

The v0.10.0 candidate includes browser and TUI voice masking. Publication awaits
the owner's approval. No release push, tag, website deployment or Homebrew update
has been performed during preparation.

## Validation

- The owner confirmed a successful real Mac–iPad masked call.
- `just precommit`, `just smoke`, `just tui-smoke`, `just turn-check` and
  `just screenshots` passed during preparation. Repeat the required suites
  after the final local commit before requesting publication approval.
- TUI smoke includes masked browser/TUI calls in both WebRTC roles and masked
  TUI/TUI audio continuing across a socket drop.
- The production Docker image passes the voice-product browser suite. Lab and
  Tidewave routes return 404; development credentials and lab code are absent.
- All 40 website desktop/mobile locale layouts and 120 TUI locale/layout cases
  passed. The masking controls and recognition warning fit an 80×24 terminal.
- macOS arm64 and Ubuntu 24.04 x86_64 archives unpack and pass version/helper
  checks. The Linux renderer NIF also loads in a fresh runtime with the expected
  system libraries. Archives include the required licenses and reject duplicate
  app versions. macOS archives omit AppleDouble metadata.

Linux validation ran under emulation with Clang and Erlang's QEMU JIT mapping
workaround in disposable images. Shipped defaults are unchanged. Temporary VM
swap was removed. Native Linux CI remains required after pushing and before
tagging.

## Publication sequence

1. Obtain approval, push the prepared commit, and wait for all native macOS/Linux
   CI checks to pass. Fix any failures before tagging.
2. Tag and push `v0.10.0`; the release workflow builds both published archives
   and uses [`v0.10.0.md`](v0.10.0.md) as the release notes.
3. Render and publish the Homebrew formula from the published CI checksums.
   The local formula is a validation artifact; its local hashes are not a
   substitute for the published archives' hashes.
4. Deploy the website through `just deploy` from the clean, pushed, green commit.
5. Close superseded Dependabot PRs with the corresponding release commit and
   retain the explicit renderer 0.18 follow-up.
